05 / 技術分析：觀察與假設分開看

使用較保守的工程診斷方式，避免把現象誤判為確定的故障零件。

假設 1：USB-C 電源／連線協商狀態不穩

即使 UA520C 未接 HDMI，Surface 仍可能跳出電力警告，顯示異常至少部分發生在 USB-C 端。然而 Windows 警告不等於已實測到 5V 電壓下降，也無法單憑通知判斷 UA520C 異常耗電。

假設 2：HDMI 熱插拔、HPD 或 EDID 狀態未正確更新

BASEUS 串接後曾無訊號且 Windows 偵測不到外接螢幕，符合連接偵測或顯示模式協商失敗的可能症狀。但未以測試儀量測 HPD、DDC、EDID，因此尚無法指認特定訊號故障。

假設 3：完整斷線後的重新初始化改善相容性

HDMI 先接與 USB-C 先接都各成功 5/5，更支持「完整斷開後重連可能有幫助」，而非「一定要照某個特定順序」。仍需要日常切換和睡眠喚醒觀察才能確認。

暫定診斷

UA520C 與 BASEUS 並非完全不相容。這組設備曾出現間歇性的連接偵測失敗，而 USB 電力警告是否與 HDMI 問題具有共同根因，現有資料不足以證實。

06 / 使用建議與是否送修

目前：保留現有設備，不急著購買替代品

既然完整重新連接後兩種接法都可成功，現在沒有充分證據支持立即更換 BASEUS Switch、購買 EDID Emulator 或外接供電設備。

日常使用：優先觀察切換、睡眠喚醒與不拔線重連

如果只有切換通道／喚醒時容易無訊號，則 HDMI 連接狀態管理值得優先調查；若 UA520C 直連螢幕也開始失敗，則應轉向 USB-C 端檢查。

若警告持續：向 TP-Link 反映並申請檢測意見

UA520C 未接 HDMI 也反覆跳出 USB 電力警告，是值得向原廠反映的獨立現象。保固內可詢問是否能進行裝置電源協商與相容性檢測，但現階段無法斷定硬體故障。
